# Этап 0.14: WeakMap и WeakSet

Начата native реализация `WeakMap` и `WeakSet`. Добавлены конструкторы с iterable, динамический вызов `set`/`add`, IteratorClose при ошибке добавления, методы `WeakMap.prototype.set/get/has/delete` и `WeakSet.prototype.add/has/delete`, а также собственные `constructor` и `Symbol.toStringTag`. Ключи и значения WeakSet ограничены объектами согласно ES2020; `symbols-as-weakmap-keys` из более поздней редакции не включены.

Слабые записи имеют отдельный тип heap allocation. GC трассирует связь между записями, но не ключ; значение WeakMap помечается только при достижимом ключе. Проход значений повторяется до неподвижной точки, после чего записи с недостижимыми ключами удаляются из коллекции. Есть Windows GC stress тесты живого ключа, цепочки ephemeron и работы после очистки мёртвых ключей, а также целевой Linux native тест. Локальный Windows набор WeakMap/WeakSet прошёл **7/7**.

Test262 для методов: `WeakMap.set` **19/20**, `get` **11/13**, `has` **18/20**, `delete` **19/22**; `WeakSet.add` **19/22**, `has` **18/20**, `delete` **19/20**. Все оставшиеся отказы в этих группах отмечены `symbols-as-weakmap-keys` либо проверяют символьные ключи, добавленные после ES2020. Проверки iterable-конструкторов и ошибок итератора: WeakMap **9/10**, WeakSet **5/6**; по одному отказу также относится к символьным ключам. Остальные группы и длительная проверка освобождения слабых записей ещё открыты.

Ранее падавшие Test262 тесты `Set.prototype` с receiver `WeakSet` теперь прошли **7/7**, аналогичные тесты `Map.prototype` с receiver `Set` и `WeakMap` прошли **10/10** в каждой группе.

Исправлена общая фабрика конструкторов: `Map.length`, `Set.length`, `WeakMap.length` и `WeakSet.length` равны 0. Их четыре Test262 проверки прошли **4/4**. Выборочные верхнеуровневые тесты конструкторов и прототипов WeakMap/WeakSet прошли после исправления длины; полный каталог ещё не проверен.
