# Этап 0.14: WeakMap и WeakSet

Начата native реализация `WeakMap` и `WeakSet`. Добавлены конструкторы с iterable, динамический вызов `set`/`add`, IteratorClose при ошибке добавления, методы `WeakMap.prototype.set/get/has/delete` и `WeakSet.prototype.add/has/delete`, а также собственные `constructor` и `Symbol.toStringTag`. Ключи и значения WeakSet ограничены объектами согласно ES2020; `symbols-as-weakmap-keys` из более поздней редакции не включены.

Слабые записи имеют отдельный тип heap allocation. GC трассирует связь между записями, но не ключ; значение WeakMap помечается только при достижимом ключе. Проход значений повторяется до неподвижной точки, после чего записи с недостижимыми ключами удаляются из коллекции. Есть Windows GC stress тесты живого ключа, цепочки ephemeron и работы после очистки мёртвых ключей, а также целевой Linux native тест. Локальный Windows набор WeakMap/WeakSet прошёл **7/7**.

Test262 для методов: `WeakMap.set` **19/20**, `get` **11/13**, `has` **18/20**, `delete` **19/22**; `WeakSet.add` **19/22**, `has` **18/20**, `delete` **19/20**. Все оставшиеся отказы в этих группах отмечены `symbols-as-weakmap-keys` либо проверяют символьные ключи, добавленные после ES2020. Проверки iterable-конструкторов и ошибок итератора: WeakMap **9/10**, WeakSet **5/6**; по одному отказу также относится к символьным ключам.

Ранее падавшие Test262 тесты `Set.prototype` с receiver `WeakSet` теперь прошли **7/7**, аналогичные тесты `Map.prototype` с receiver `Set` и `WeakMap` прошли **10/10** в каждой группе.

Исправлена общая фабрика конструкторов: `Map.length`, `Set.length`, `WeakMap.length` и `WeakSet.length` равны 0. Их четыре Test262 проверки прошли **4/4**.

Полный прогон верхнеуровневых файлов Test262 `WeakMap`/`WeakSet` дал **37/43**. Два отказа требуют символьных слабых ключей более поздней редакции, два — отсутствующий `Reflect.construct`, два — cross-realm. Эти зависимости остаются открытыми для общего покрытия ES2020.

Команда `npm run check:weak-memory` компилирует четыре Linux native программы. `WeakMap` и `WeakSet` со 100 временными ключами и блоками по 1 МиБ завершились под ограничением виртуальной памяти **96 МиБ**; контрольные `Map` и `Set` завершились без лимита, но не уложились в тот же лимит. Проверка прошла под WSL. Это подтверждает ограниченный рост памяти для данного сценария, но не заменяет полный стресс-аудит GC.
