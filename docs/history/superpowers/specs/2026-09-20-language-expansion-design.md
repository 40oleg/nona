# Расширение Nona: проект архитектуры и границ

Дата: 2026-09-20. Статус: **принят подход собственного AOT; пользователь исключил динамический eval/Function**.

## 1. Понимание запроса

Пользователь просит вести документацию и реализовать «пункты 1, 2, 3 — всё».
На уточняющий вопрос получен ответ: **«Разделы 1–3: весь язык до ES2020»**.
Объём: раздел 1 (базовый язык), раздел 2 (ES2015), раздел 3 (ES2016–ES2020)
предыдущего перечня. Это не только объекты, замыкания и управление памятью.

Объём подтверждён пользователем. После рассмотрения архитектуры пользователь
уточнил: «без динамического eval и Function». Обычные функции, стрелки,
генераторы, async-функции и замыкания остаются в объёме.

## 2. Сохраняемые ограничения

- TypeScript для разработки компилятора.
- Собственный генератор x64 и PE32+ для Windows.
- EXE запускается без Node.js, C-компилятора, LLVM и готового JS-интерпретатора.
- Windows API разрешены; новый системный импорт документируется и проверяется.
- Ошибки компиляции не портят существующий выходной файл.
- Поддержка означает семантику JavaScript, включая побочные эффекты, исключения,
  порядок вычисления и ошибочные программы; одной узнаваемости синтаксиса мало.
- Существующая спецификация остаётся описанием v0.1, новый документ не переписывает
  историю её реализации.

## 3. Варианты подхода

### A. Развивать собственный backend и runtime — рекомендуемый

Сначала объектная модель, heap, окружения, вызовы и исключения; затем добавлять
синтаксис и библиотеку через вертикальные этапы с запускаемыми EXE.
Сохраняет назначение проекта и контроль над генерацией машинного кода.
Требует реализации крупного языкового runtime; полный ES2020 не сводится к
настройке TypeScript target или добавлению нескольких правил в parser.

### B. Встроить готовый движок

Может ускорить достижение широкой совместимости, но меняет исходное требование
самостоятельной реализации. Не выбран и без изменения требований не применяется.

### C. Транспилировать новый синтаксис в текущий поднабор

Сам по себе вариант не решает задачу: у Nona нет даже объектов, замыканий и
исключений, на которые опираются такие преобразования. Преобразования синтаксиса
полезны позднее внутри варианта A, после появления корректного runtime.

## 4. Архитектура общего основания

### Значения и память

Сохранить 16-байтовый tagged Value как начальный ABI. Добавить ссылки на heap
объектов; функции и массивы — виды объектов с общей инфраструктурой свойств.
Для Symbol и BigInt предусмотреть самостоятельные теги.

Использовать точный немещающий mark-and-sweep GC: стабильные адреса упрощают
первую реализацию собственного backend. Все сохраняемые Value в кадрах, глобалах,
окружениях, аргументах и временных runtime-корнях доступны сборщику в safepoints.
Мёртвые временные значения очищаются; иначе корни из старых stack slots будут
удерживать память. Литералы в read-only памяти не освобождаются. Рабочие буферы
числовых алгоритмов требуют отдельного проверяемого жизненного цикла.

WeakMap/WeakSet добавляются после сильного графа: достижимость значений WeakMap
зависит от достижимости ключей (ephemeron processing), обычного прохода по всем
полям недостаточно. Простое reference counting не выбрано из-за циклов.

### Объекты

Единые внутренние операции Get/Set/Has/Delete/DefineOwnProperty/OwnKeys и доступ
к prototype. Они учитывают дескрипторы, getters/setters, receiver, strict/sloppy
поведение и порядок ключей. Объектные ключи — строки и символы.

Массивы реализуют специальные правила length, holes и числовых индексов;
отсутствующий элемент отличается от свойства со значением undefined.
В дальнейшем Proxy перехватывает эти операции и проверяет их инварианты.

### Окружения и функции

Ввести явные lexical/function/global environment records и bindings с признаками
initialized/mutable. Захваченные переменные разделяются между замыканиями,
а не копируются при каждом чтении. Итерационные окружения let/const создаются
по правилам языка. Hoisting, TDZ и early errors принадлежат отдельному binding-слою.

Функциональный объект хранит код, окружение, правила this, constructability и
метаданные. Вызов передаёт callee, this, new.target, аргументы и канал результата.
Рекурсия, bind и call/apply используют тот же протокол. В sloppy-функциях нужны
mapped arguments; в strict и иных предусмотренных стандартом случаях — unmapped.

### Исключения и управление потоком

IR различает нормальный результат и abrupt completion. Исключение передаётся
явно через соглашение вызова; finally обрабатывает throw/return/break/continue
и может заменить прежний результат. Это JS-механизм, отдельный от Windows unwind.
Runtime TypeError/ReferenceError/RangeError должны перехватываться JS-кодом.

### Генераторы и асинхронность

Приостановленные функции имеют heap frame и состояние продолжения. Нужны next,
throw, return, IteratorClose, yield* и корректное завершение через finally.
Promise reactions выполняются через очередь jobs; завершение entry point
обрабатывает очередь до завершения доступной работы. Нельзя выполнять then
синхронно и называть это Promise. Async-функции и async-генераторы используют
эти механизмы; timers и сеть не добавляются как скрытые требования.

## 5. Полный вариант: дополнительные подсистемы

| Подсистема | Граница результата |
| --- | --- |
| Базовая библиотека | Object/Function/Array/String/Number/Boolean/Math/Date/JSON/Error и глобальные функции по выбранной редакции |
| RegExp | Собственный разбор и исполнение, включая Unicode, named groups, lookbehind, s/u/y, matchAll |
| ES2015 коллекции | Map/Set и слабые коллекции с правильной идентичностью ключей |
| Бинарная память | ArrayBuffer/DataView/typed arrays, затем BigInt views |
| Общая память | SharedArrayBuffer/Atomics с проверяемым agent harness; Worker API не следует автоматически из ES2020 |
| Модули | Граф, циклы, live bindings, namespace objects, linking/evaluation, dynamic import, import.meta |
| BigInt | Произвольная целочисленная точность, операторы и ошибки смешивания с Number |
| Синтаксис ES2015–2020 | Каждый пункт пользовательского перечня, включая семантические уточнения, а не только самые заметные операторы |
| Динамический исходник | eval и динамические конструкторы Function/GeneratorFunction/AsyncFunction/AsyncGeneratorFunction исключены пользователем |

### Принятое исключение: eval и Function

Произвольный текст eval/Function может появиться только во время исполнения.
Обычная предварительная AOT-компиляция не способна скомпилировать заранее
неизвестный текст. Запуск Node.js при сборке, вычисление результата заранее или
обработка только строковых литералов не являются выполнением полного требования.

По решению пользователя эти операции исключены. Собственный динамический
компилятор, исполняемые страницы для нового кода и готовые интерпретаторы не
добавляются. Доступ к динамическим конструкторам через `.constructor` тоже не
должен молчаливо обходить это ограничение. `Function.prototype.call/apply/bind`
и функциональные объекты не исключены. Соответствие всему ES2020 без этой
оговорки не заявляется.

### Модули и среда

Первый предлагаемый module host разрешает относительные файлы из графа проекта
и сохраняет граф внутри EXE. Вычисляемый dynamic import выбирает модуль из
сохранённого графа; неизвестный модуль приводит к rejection. Новые исходники
во время исполнения не компилируются. Это явный контракт host loader для AOT.
`import.meta` и разрешение спецификаторов содержат host-defined части; их контракт
записывается отдельно. Сеть, DOM, npm-resolution и Node API автоматически не входят.

Proper tail calls, ранее явно исключённые из списка поддержанного V8, не включаются
молчаливо. Соответствие всей редакции ES2015 без этой оговорки не заявляется.

## 6. Очерёдность работ и документация

1. Общие Value/heap/root ABI и проверяемая инфраструктура GC.
2. Объекты, свойства, дескрипторы и массивы; end-to-end вертикальные проверки.
3. Функции-значения, lexical environments, замыкания, this/new/arguments.
4. Исключения, strict mode и оставшиеся базовые инструкции.
5. Базовая библиотека, преобразования объектов и RegExp.
6. Блочные объявления и остальной синтаксис ES2015; протоколы итерации и классы.
7. Коллекции, Proxy/Reflect, бинарная память и генераторы.
8. Promise/jobs, async-механизмы и модули.
9. ES2016–2020: оставшиеся операторы/API, BigInt, shared memory.
10. Полная интеграционная проверка оговорённого поднабора до ES2020, отчёт Test262
    и документация исключений eval/динамических конструкторов и AOT module host.

Каждый этап получает отдельный подробный план и связанный набор acceptance tests.
Порядок внутри этапа определяется зависимостями; GC нельзя добавлять последним
без заранее определённого протокола корней. Выполнение только первого этапа не
означает выполнение всего запроса.

Документы: `docs/language-support.md` — фактическая матрица,
`docs/history/development-log.md` — журнал, `docs/README.md` — индекс и правила.
Для всех запрошенных функций создаётся детальный реестр
приёмки: идентификатор требования, реализация, тест, статус и ограничения.

## 7. Проверки

- Исходная точка: `npm.cmd run check` — 147 pass, 0 fail, 1 skip из 148.
- Новая функция начинается с воспроизводящего отсутствие возможности теста.
- После реализации запускается настоящий EXE с проверкой результата, исключений
  и порядка побочных эффектов; oracle Node используется только при тестировании.
- GC: циклы, замыкания после возврата, корни в аргументах/getters и временных
  значениях, повторная сборка, удерживаемые и освобождаемые графы, давление памяти.
- Объекты: getter/setter побочные эффекты, non-writable/non-configurable свойства,
  прототипные цепочки, массивные holes, shrink length и порядок ключей.
- Функции: независимые и разделяемые замыкания, рекурсия, this/new, число аргументов,
  перезапись функций, затенение и переменные цикла.
- Исключения: все виды abrupt completion через finally, межфункциональный throw,
  ошибки свойств и невалидные программы.
- Async: порядок promise jobs, rejection propagation, thenable assimilation,
  приостановка и закрытие итераторов.
- Проверки PE/ABI, самостоятельного запуска и сохранности файлов остаются
  обязательными; их нельзя удалить ради прохождения нового набора.
- Подключить закреплённую ревизию Test262 с явно определённым host harness.
  В отчёте показывать passed/failed/skipped и причины исключений, а не только процент.
