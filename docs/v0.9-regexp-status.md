# RegExp: этап 0.9

Срез: 27 сентября 2026 года. Работа идёт в общей ветке `work/v0.6-v0.14`; PR будет один после завершения всего диапазона.

Литералы RegExp проходят через lexer, AST, binder и IR. Конструктор создаёт native объект с исходным шаблоном, флагами `gimsuy` и собственным `lastIndex`; внутренние строки отслеживает GC. Реализованы проверки флагов и структуры шаблона, копирование RegExp, `Symbol.match`-подобные аргументы, геттеры `source`/`flags` и отдельных флагов, `toString()`, `test()`, `exec()`, а также `RegExp[Symbol.species]`. Parser VM вызывается при создании RegExp и сразу отклоняет неверные квантификаторы, синтаксис групп, недопустимые identity escapes при `u` и ссылки на отсутствующие захваты. `test()` вызывает переопределённое свойство `exec`.

Быстрый native matcher обрабатывает простые литералы, точку, классы, сокращённые классы, якоря, границы слова, некоторые повторы и литеральные альтернативы. Для шаблонов с группами, общими альтернативами и повторами `exec()` вызывает VM, написанный на поднаборе JavaScript и скомпилированный самим Nona в отдельном IR. VM разбирает символьные классы один раз при создании RegExp, проверяет диапазоны и использует те же разобранные элементы при сопоставлении; поддержаны литералы, сокращённые классы, Unicode properties, `\x`, `\u` и Unicode code points. Классы с escape-последовательностями исполняет VM. VM разбирает последовательности, группы (включая именованные), альтернативы, классы, жадные и ленивые квантификаторы `*`, `+`, `?`, `{m,n}`, обратные ссылки и базовые lookahead/lookbehind. Захваты обновляются при откате и сбрасываются на новой итерации повторения. Результат `exec()` содержит захваты, `index`, `input` и `groups`, причём именованные `groups` имеют null-прототип. Ядро VM создаётся при первой проверке шаблона и затем используется при сложных вызовах `exec()`.

Поддержка `u` остаётся частичной: native точка захватывает суррогатную пару и `lastIndex` считает UTF-16 единицы; поиск не начинает совпадение со второй половины пары, поддерживается отдельный escape `\uNNNN`. VM обрабатывает суррогатные пары как одну кодовую точку для точки, простых классов и литералов, поддерживает `\u{...}`. Добавлены `\p{…}`/`\P{…}` с данными Unicode 17 для общих категорий, Script, Script_Extensions и двоичных свойств ES2020, в том числе внутри классов. Таблицы генерирует `scripts/generate-regexp-unicode.py` из официального UCD. Полный Unicode case folding и все правила направления lookbehind ещё не реализованы. Остаётся дополнить parser VM до полной грамматики и валидации шаблона при создании RegExp, все escape-последовательности, точная семантика backtracking и ограничение ресурсов для патологических шаблонов. Часть интеграции с методами String и Symbol hooks уже выполнена в [этапе 0.10](v0.10-regexp-string-status.md).

Проверки: выбранная группа Test262 `built-ins/RegExp/prototype/exec` — **76/79**. Три оставшихся файла проверяют поздние флаги `d`/`v` или разрешение повторных имён групп после ES2020. Группа `RegExp[Symbol.species]` — **4/4**. Локальные проверки RegExp/VM после валидации escapes и ссылок — **41/41**, включая стрессовую GC для захватов. Полный Windows-прогон после внедрения VM и исправления точки входа: **1795 pass, 0 fail, 1 skip из 1796**; последующее Unicode-изменение проверено локально. Четыре отдельные Linux-проверки RegExp/VM со стрессовой GC и без неё прошли. Эти выборки не доказывают полного покрытия ES2020 RegExp.
