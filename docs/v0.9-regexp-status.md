# RegExp: этап 0.9

Срез: 27 сентября 2026 года. Работа идёт в общей ветке `work/v0.6-v0.14`; PR будет один после завершения всего диапазона.

Литералы RegExp проходят через lexer, AST, binder и IR. Конструктор создаёт native объект с исходным шаблоном, флагами `gimsuy` и собственным `lastIndex`; внутренние строки отслеживает GC. Реализованы базовые проверки флагов и структуры шаблона, копирование RegExp, `Symbol.match`-подобные аргументы, геттеры `source`/`flags` и отдельных флагов, `toString()`, `test()`, `exec()`, а также `RegExp[Symbol.species]`. `test()` вызывает переопределённое свойство `exec`.

Быстрый native matcher обрабатывает простые литералы, точку, классы, сокращённые классы, якоря, границы слова, некоторые повторы и литеральные альтернативы. Для шаблонов с группами, общими альтернативами и повторами `exec()` вызывает VM, написанный на поднаборе JavaScript и скомпилированный самим Nona в отдельном IR. VM разбирает последовательности, группы (включая именованные), альтернативы, классы, жадные и ленивые квантификаторы `*`, `+`, `?`, `{m,n}`, обратные ссылки и базовые lookahead/lookbehind. Захваты обновляются при откате и сбрасываются на новой итерации повторения. Результат `exec()` содержит захваты, `index`, `input` и `groups`, причём именованные `groups` имеют null-прототип. VM создаётся при первом сложном вызове, чтобы обычные программы и стрессовая GC не платили за его построение на старте.

Поддержка `u` остаётся частичной: native точка захватывает суррогатную пару и `lastIndex` считает UTF-16 единицы; поиск не начинает совпадение со второй половины пары, поддерживается отдельный escape `\uNNNN`. VM обрабатывает суррогатные пары как одну кодовую точку для точки, простых классов и литералов, поддерживает `\u{...}`. Добавлены `\p{…}`/`\P{…}` с данными Unicode 17 для общих категорий, Script, Script_Extensions и двоичных свойств ES2020, в том числе внутри классов. Таблицы генерирует `scripts/generate-regexp-unicode.py` из официального UCD. Полный Unicode case folding и все правила направления lookbehind ещё не реализованы. Нужны полная валидация синтаксиса при создании RegExp, все escape-последовательности, точная семантика backtracking и ограничение ресурсов для патологических шаблонов. Интеграция с методами String и Symbol hooks относится к этапу 0.10.

Проверки: выбранная группа Test262 `built-ins/RegExp/prototype/exec` — **76/79**. Три оставшихся файла проверяют поздние флаги `d`/`v` или разрешение повторных имён групп после ES2020. Группа `RegExp[Symbol.species]` — **4/4**. Локальные проверки RegExp и VM после Unicode-изменений — **36/36**, включая стрессовую GC для захватов. Полный Windows-прогон после внедрения VM и исправления точки входа: **1795 pass, 0 fail, 1 skip из 1796**; последующее Unicode-изменение проверено локально. Четыре отдельные Linux-проверки RegExp/VM со стрессовой GC и без неё прошли. Эти выборки не доказывают полного покрытия ES2020 RegExp.
