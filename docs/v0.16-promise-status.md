# 0.16 Promise и очередь jobs — текущий срез

Добавлена очередь Promise jobs, которая исполняется после пользовательского `main` до завершения Windows/Linux процесса. Начальная реализация включает конструктор, resolving functions, thenable assimilation, `then`, `catch`, `finally`, `resolve`, `reject`, `all`, `allSettled` и `race`. Состояние Promise хранится во внутреннем WeakMap. Обработчики вызываются из очереди; новые jobs продолжают выполняться до её опустошения.

Проверка: три локальных native GC stress теста Promise с точным сравнением вывода с Node.js 26; совокупный набор Promise/Proxy/Reflect — 18/18. Отдельный Linux ELF smoke Promise совпал с Node.js 26; набор Linux compat — 77/77. Выбранные синхронные каталоги Test262 на Windows: `Promise/all` 40 pass, 1 fail, 57 skip; `allSettled` 46/1/57; `race` 30/1/63; `reject` 13/1/1. Оставшийся fail в каждой из этих четырёх групп — `ctx-non-ctor.js`, использующий ранее исключённый динамический `eval`. В `Promise/resolve` до последних исправлений было 14/3/13; адресные проверки capability, имени и неконструируемости функций затем прошли. `Promise/prototype/then` до исправления неконструируемости метода было 15/1/59; адресный случай затем прошёл. `Promise/prototype/finally` до исправления неконструируемости обработчиков было 16/1/12; адресный случай затем прошёл.

Этап **не закрыт**: текущий Test262 runner пропускает большинство async тестов, поэтому нужен отдельный полный async gate. Не завершены политика необработанных отклонений, все варианты порядка side effects при выделении Promise через `newTarget`, cross-realm, проверка всех наследуемых/изменяемых intrinsics и защита внутренней точки drain от пользовательского кода. Синхронный root-каталог `built-ins/Promise` до последних исправлений дал 27 pass, 5 fail, 26 skip; один fail связан с порядком проверки executor и `newTarget.prototype`, один — cross-realm, три адресно исправлены позднее. Отсутствует полное доказательство ES2020-соответствия Promise.
