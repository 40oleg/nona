# Этап 0.12: SharedArrayBuffer и Atomics

Начата native реализация SharedArrayBuffer с отдельным внутренним типом и байтовым блоком, доступным нескольким видам. Конструктор, `byteLength`, `Symbol.species`, `Symbol.toStringTag` и `slice` работают на Windows и Linux x64. `DataView` и typed arrays принимают SharedArrayBuffer; запись через один вид видна через другой. Буфер и его прототип трассируются GC, что подтверждено Windows stress тестом.

Test262: `SharedArrayBuffer.prototype.byteLength` **9/9**, `slice` **32/32**; отдельные проверки нулевой инициализации, нулевой длины и `ToIndex` **3/3**. Регрессионные группы `ArrayBuffer.prototype.byteLength` **10/10** и `ArrayBuffer.prototype.slice` **33/33**. Целевой Linux native тест с совместным доступом и `slice` прошёл. Общий первый прогон каталога SharedArrayBuffer до подключения видов и `slice` дал **31/104**; его результат устарел и не служит оценкой текущего покрытия.

SharedArrayBuffer пока использует память процесса. Модель нескольких агентов, синхронизация `wait`/`notify` и многопоточные тесты ещё не реализованы. Опции growable SharedArrayBuffer из более поздних редакций стандарта также отсутствуют.

Добавлен глобальный объект `Atomics` и метод `isLockFree` для ширин 1, 2, 4 и 8 байт на x64. Test262: **7/7**; целевые Windows и Linux native тесты прошли. В x64 assembler добавлены кодировщики `xchg`, `lock xadd`, `lock cmpxchg` и `mfence`, проверенные отдельным тестом байтов инструкций.

Добавлен native `Atomics.load`: проверка целочисленного вида до преобразования индекса, границ и detachment, выравненное чтение 8/16/32/64 бит с барьером, знаковое расширение и возврат BigInt. Первый Test262 дал **12/14**: два теста `good-views` использовали `Atomics.store`, которого на тот момент ещё не было. Целевые Windows и Linux native тесты прошли.

Добавлен native `Atomics.store` с `xchg` по ширине элемента. Для Number результатом является `ToIntegerOrInfinity`, а в память записываются младшие биты; для BigInt используется точное `ToBigInt` с отказом от Number и сохранением исходного значения для возврата. Повторный Test262: `store` **16/17** (единственный отказ требует immutable ArrayBuffer), `load` **14/14**. Целевые Windows и Linux native тесты прошли.

Добавлены native `Atomics.add`, `sub`, `exchange`, `and`, `or`, `xor` и `compareExchange` с возвратом прежнего значения, приведением Number/BigInt и атомарными x64 инструкциями. Каждая из первых шести групп Test262 проходит **15/16**, `compareExchange` — **16/17**; в каждой единственный отказ требует immutable ArrayBuffer более поздней редакции стандарта. Проверены отдельные Windows и Linux native сценарии, в том числе переполнение и преобразование ожидаемого значения для `Uint32Array`.

Добавлен `Atomics.notify` с проверкой `Int32Array`/`BigInt64Array`, индекса и преобразованием `count` в порядке стандарта. Пока ожидающих агентов нет, результат равен 0. Целевые Windows и Linux native тесты прошли; Test262 — **32/52**. Большинство отказов требуют тестового агента или возможностей более поздних редакций (immutable/resizable SharedArrayBuffer). Пробуждение ожидающих агентов и `Atomics.wait` остаются открытыми.

Начат `Atomics.wait`: реализованы проверка типа и общего буфера, порядок преобразования индекса, ожидаемого значения и таймаута, результаты `not-equal` и `timed-out`. Конечное ожидание использует `WaitOnAddress` из KERNELBASE на Windows и `futex` на Linux; целевые native тесты на обеих платформах прошли. Test262: отрицательный таймаут **2/2**, порядок проверки типа **3/3**, неверный индекс **2/2**; из восьми тестов с `for-timeout.js` прошли пять, три агентных теста не компилируются из-за отсутствующей модели агентов. Полное пробуждение `notify`, точное число ожидающих, FIFO и многопоточные тесты остаются открытыми.

Полный каталог Test262 `built-ins/Atomics/wait` дал **31/77**: 43 файла не компилируются из-за вызовов `$262.agent`, для которых пока нет native модели агентов; два runtime отказа помечены `CanBlockIsFalse` и требуют иной политики host harness; один проверяет growable SharedArrayBuffer после ES2020. Среди завершившихся применимых тестов новых отказов не выявлено. Этот результат подтверждает необходимость agent harness, но не закрывает многопоточную семантику `wait`/`notify`.
