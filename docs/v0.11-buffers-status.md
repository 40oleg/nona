# Бинарная память: этап 0.11

Срез: 27 сентября 2026 года. Работа идёт в общей ветке `work/v0.6-v0.14`; этап 0.11 не завершён.

Добавлен native `ArrayBuffer` с отдельным нулевым блоком байтов, длиной, прототипом и трассировкой блока в GC. Конструктор требует `new`, преобразует длину по `ToIndex` для поддержанного диапазона, сохраняет прототип подкласса. Есть accessor `ArrayBuffer.prototype.byteLength`, `ArrayBuffer.prototype.slice`, `Symbol.toStringTag` и `ArrayBuffer[Symbol.species]`. `slice` копирует байты в новый буфер с учётом границ и species.

Проверки Windows: три локальных теста, включая GC stress и `slice`; совместно с тестами глобальных свойств — 16/16. Test262: `ArrayBuffer.prototype.byteLength` 7/10, `ArrayBuffer[Symbol.species]` 4/4, `ArrayBuffer.prototype.slice` 32/33; отдельные тесты конструктора для ToIndex, нулевой и отрицательной длины — 3/3. Единственный отказ `slice` требует SharedArrayBuffer. Три отказа `byteLength` требуют detachment, DataView/typed arrays и SharedArrayBuffer. Linux ELF для ArrayBuffer успешно скомпилирован; исполнение теста пропущено, поскольку WSL недоступен в текущем окружении.

Добавлен `ArrayBuffer.isView`; он распознаёт объекты DataView и возвращает false для остальных доступных типов. Test262: 12/17; оставшиеся случаи требуют typed arrays.

Добавлен native `DataView`: конструктор проверяет ArrayBuffer, смещение и длину, поддерживает наследование; доступны `buffer`, `byteOffset`, `byteLength`, `getInt8`, `getUint8`, `setInt8`, `setUint8` и `@@toStringTag`. Ссылка на буфер трассируется GC. Однобайтовые методы проверены на совместном буфере, копии после `slice`, преобразовании аргументов и stress GC. Локальные проверки ArrayBuffer/DataView — 8/8, вместе с тестами глобальных свойств — 21/21; проверка подкласса DataView в Test262 прошла. Linux ELF собран, выполнение пропущено из-за недоступного WSL.

Осталось реализовать detachment и остальные методы чтения/записи DataView (16/32-битные целые, float32/float64, BigInt64/BigUint64), все typed arrays включая BigInt, их методы, bounds/species/итераторы, а также завершить `ArrayBuffer.isView` и проверки Test262 и Linux. Выделение памяти сейчас ограничено 2³¹−1 байт; при нехватке памяти native allocator завершает процесс с общей ошибкой. Это промежуточное ограничение, не заявка на полную семантику ArrayBuffer.
