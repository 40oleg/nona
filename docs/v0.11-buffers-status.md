# Бинарная память: этап 0.11

Срез: 27 сентября 2026 года. Работа идёт в общей ветке `work/v0.6-v0.14`; этап 0.11 не завершён.

Добавлен native `ArrayBuffer` с отдельным нулевым блоком байтов, длиной, прототипом и трассировкой блока в GC. Конструктор требует `new`, преобразует длину по `ToIndex` для поддержанного диапазона, сохраняет прототип подкласса. Есть accessor `ArrayBuffer.prototype.byteLength`, `Symbol.toStringTag` и `ArrayBuffer[Symbol.species]`.

Проверки Windows: два локальных теста, включая GC stress; совместно с тестами глобальных свойств — 15/15. Test262: `ArrayBuffer.prototype.byteLength` 7/10, `ArrayBuffer[Symbol.species]` 4/4; отдельные тесты конструктора для ToIndex, нулевой и отрицательной длины — 3/3. Три отказа `byteLength` требуют detachment, DataView/typed arrays и SharedArrayBuffer. Linux ELF для ArrayBuffer успешно скомпилирован; исполнение теста пропущено, поскольку WSL недоступен в текущем окружении.

Осталось реализовать `ArrayBuffer.prototype.slice`, `ArrayBuffer.isView`, detachment и доступ к байтам через DataView, все typed arrays включая BigInt, их методы, bounds/species/итераторы, а также проверки Test262 и Linux. Выделение памяти сейчас ограничено 2³¹−1 байт; при нехватке памяти native allocator завершает процесс с общей ошибкой. Это промежуточное ограничение, не заявка на полную семантику ArrayBuffer.
