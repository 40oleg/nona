# Бинарная память: этап 0.11

Срез: 27 сентября 2026 года. Работа идёт в общей ветке `work/v0.6-v0.14`; этап 0.11 не завершён.

Добавлен native `ArrayBuffer` с отдельным нулевым блоком байтов, длиной, прототипом и трассировкой блока в GC. Конструктор требует `new`, преобразует длину по `ToIndex` для поддержанного диапазона, сохраняет прототип подкласса. Есть accessor `ArrayBuffer.prototype.byteLength`, `ArrayBuffer.prototype.slice`, `Symbol.toStringTag` и `ArrayBuffer[Symbol.species]`. `slice` копирует байты в новый буфер с учётом границ и species.

Проверки Windows: три локальных теста, включая GC stress и `slice`; совместно с тестами глобальных свойств — 16/16. Test262: `ArrayBuffer.prototype.byteLength` 7/10, `ArrayBuffer[Symbol.species]` 4/4, `ArrayBuffer.prototype.slice` 32/33; отдельные тесты конструктора для ToIndex, нулевой и отрицательной длины — 3/3. Единственный отказ `slice` требует SharedArrayBuffer. Три отказа `byteLength` требуют detachment, DataView/typed arrays и SharedArrayBuffer. Linux ELF для ArrayBuffer успешно скомпилирован; исполнение теста пропущено, поскольку WSL недоступен в текущем окружении.

Добавлен `ArrayBuffer.isView`; он распознаёт DataView и текущий Uint8Array, но общий набор typed arrays пока отсутствует. Test262: 12/17; оставшиеся случаи используют весь набор конструкторов typed arrays.

Начата общая основа typed arrays с native `Uint8Array`: конструктор принимает длину или существующий ArrayBuffer со смещением и длиной, объект удерживает backing buffer в GC, а индексные чтение/запись, `in` и `delete` используют специальную ветку runtime. Мутации видны через DataView и наоборот. `ArrayBuffer.isView` распознаёт экземпляры. Локальные проверки ArrayBuffer/DataView/Uint8Array — 20/20, вместе с тестами глобальных свойств — 33/33. Linux ELF собран; выполнение пропущено из-за отсутствия WSL. Полная семантика typed arrays ещё не достигнута: отсутствуют остальные типы, конструирование из iterable/array-like, общий `%TypedArray%` prototype, канонические числовые ключи, методы, итераторы и detachment.

Добавлен native `DataView`: конструктор проверяет ArrayBuffer, смещение и длину, поддерживает наследование; доступны `buffer`, `byteOffset`, `byteLength`, целочисленные методы 8/16/32 бит, `Float32`/`Float64`, `BigInt64`/`BigUint64` и `@@toStringTag`. Ссылка на буфер трассируется GC. Методы BigInt собирают и разбирают значение через две 32-битные половины, без преобразования всего 64-битного значения в Number. Методы проверены на совместном буфере, копии после `slice`, преобразовании аргументов, порядке байтов, `-0`, `NaN` и stress GC. Локальные проверки ArrayBuffer/DataView — 14/14, вместе с тестами глобальных свойств — 27/27. Проверка подкласса DataView в Test262 прошла. Linux ELF собран, выполнение пропущено из-за недоступного WSL.

Методы BigInt DataView и `ArrayBuffer.prototype.slice` используют заранее захваченные встроенные функции. Целевая проверка после подмены `Function.prototype.call`, `Number` и `Math.trunc` прошла. Локальные ArrayBuffer/DataView тесты — 15/15, вместе с глобальными свойствами — 28/28. Test262 для `ArrayBuffer.prototype.slice` остаётся 32/33; единственный отказ требует SharedArrayBuffer.

Осталось реализовать detachment, все typed arrays включая BigInt, их методы, bounds/species/итераторы, а также завершить `ArrayBuffer.isView` и проверки Test262 и Linux. Выделение памяти сейчас ограничено 2³¹−1 байт; при нехватке памяти native allocator завершает процесс с общей ошибкой. Это промежуточное ограничение, не заявка на полную семантику ArrayBuffer.

Для Uint8Array добавлены перечисление индексных свойств, их дескрипторы и Object.defineProperty с записью в общий backing buffer. Несовместимые атрибуты и выход за границы отклоняются. Целевые локальные тесты — 20/20, вместе с глобальными свойствами — 33/33.

Для Uint8Array добавлена классификация канонических числовых ключей: -0, отрицательные, дробные, NaN/Infinity и большие индексы не становятся обычными свойствами и не берутся из прототипа. Обычные строковые ключи, например 01 и 1e0, остаются обычными свойствами. Локальные проверки ArrayBuffer/DataView/Uint8Array — 22/22, вместе с глобальными свойствами — 35/35, включая stress GC.

Uint8Array теперь принимает iterable и array-like источники через внутренний Array.from с заранее захваченной функцией преобразования в Uint8. Значения преобразуются во время итерации; ошибка закрывает итератор. Исправлен переход для числовых свойств обычных Array в defineOwnProperty, выявленный этим путём. Целевой набор Uint8Array и Array.from — 20/20; отдельная проверка с подменой Array.from и stress GC также прошла.

Добавлен общий прототип для typed arrays с Uint8Array.values, keys, entries и Symbol.iterator. Итераторы используют текущие байты backing buffer, проверяют receiver и удерживают источник при stress GC. Остальные методы %TypedArray%.prototype, виды массивов и точная форма конструктора пока отсутствуют.

Добавлен абстрактный конструктор %TypedArray%: он является прототипом Uint8Array, владеет общим prototype и его constructor; прямой вызов и new отклоняются. Геттеры buffer/byteOffset/byteLength/length перенесены на общий прототип. Статические from/of и полная семантика @@toStringTag ещё требуют реализации.

Статический TypedArray.of (наследуется Uint8Array) вызывает конструктор receiver с числом элементов, проверяет тип и достаточную длину результата, затем последовательно приводит элементы и записывает их в backing buffer. Проверены наследование, ошибочный receiver, короткий результат и GC stress при преобразовании.

Добавлен Int8Array: конструктор по длине, ArrayBuffer и iterable/array-like, общий backing buffer, знаковое чтение индексных байтов, запись с ToInt8, дескрипторы, итераторы, распознавание ArrayBuffer.isView и TypedArray.of. Он использует существующий 1-байтовый layout; 16/32/64-битные виды пока требуют параметризации размера элемента.

Добавлен Uint8ClampedArray с общим backing buffer и точным ToUint8Clamp: NaN/отрицательные значения дают 0, верхняя граница ограничена 255, половины округляются к чётному байту. Одинаковое преобразование используется при присваивании, defineProperty, TypedArray.of и создании из iterable/array-like. Целевые проверки и GC stress прошли; Linux ELF собран, исполнение пропущено из-за недоступного WSL.

Добавлены Uint16Array и Int16Array с двухбайтовыми элементами, проверкой выравнивания byteOffset, раздельными length/byteLength, знаковым чтением, общим ArrayBuffer и little-endian индексной записью. Проверены границы вида на буфер, Object.defineProperty, TypedArray.of, итераторы и GC stress. Linux ELF собран; запуск пропущен, WSL недоступен. Следующие виды требуют 32/64-битные и floating-point операции.

Добавлены Uint32Array и Int32Array с четырёхбайтовыми элементами. Проверены преобразование с переполнением, знаковое и беззнаковое чтение, выравнивание и длина вида, общие байты с DataView, Object.defineProperty, итераторы и GC stress. Целевой регрессионный набор typed arrays и Array.from — 34/34; глобальные свойства — 13/13. Linux ELF собран, запуск пропущен из-за недоступного WSL. Следующие виды требуют 64-битные и floating-point операции; другие методы %TypedArray% также остаются.

Добавлены Float32Array и Float64Array: преобразование через ToNumber, округление Float32 при записи, сохранение NaN, Infinity и -0, доступ через общий ArrayBuffer и DataView. Проверены длина и выравнивание видов, Object.defineProperty, TypedArray.of, итераторы и stress GC. Регрессионный набор typed arrays и Array.from — 36/36; глобальные свойства — 13/13. Linux ELF собран, исполнение пропущено из-за недоступного WSL. Остаются BigInt64Array/BigUint64Array, другие методы %TypedArray%.prototype и detachment.

Добавлены BigInt64Array и BigUint64Array: точная запись/чтение 64-битных значений через BigInt без Number, оборачивание по модулю 2^64, знаковая интерпретация, общий буфер с DataView. Проверены конструкторы, TypedArray.of, Object.defineProperty, запрет Number, итераторы и stress GC. Целевой набор ArrayBuffer/DataView/typed arrays/Array.from — 52/52; глобальные свойства — 13/13. Linux ELF для BigInt видов собран; запуск пропущен из-за недоступного WSL. Остаются detachment и прочие методы %TypedArray%.prototype, а также расширенные проверки Test262.

Добавлен %TypedArray%.prototype.reverse для всех 11 числовых и BigInt видов. Метод меняет байты исходного буфера по элементам и возвращает тот же объект; проверены пустые/нечётные/чётные длины, другие представления того же буфера, 64-битные значения и stress GC. Windows регрессионный набор ArrayBuffer/DataView/typed arrays/Array.from — 54/54. В этой среде теперь удалось выполнить Linux native: полный elf.test.js — 38 успешных, 1 пропуск (отдельная проверка прямого запуска ELF сообщает о недоступном WSL), 0 ошибок; семь целевых Linux-тестов typed arrays — 7/7 без пропусков. Это подтверждает выбранные сценарии, не весь Linux backend.
