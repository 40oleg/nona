# Бинарная память: этап 0.11

Срез: 27 сентября 2026 года. Работа идёт в общей ветке `work/v0.6-v0.14`; этап 0.11 не завершён.

Добавлен native `ArrayBuffer` с отдельным нулевым блоком байтов, длиной, прототипом и трассировкой блока в GC. Конструктор требует `new`, преобразует длину по `ToIndex` для поддержанного диапазона, сохраняет прототип подкласса. Есть accessor `ArrayBuffer.prototype.byteLength`, `ArrayBuffer.prototype.slice`, `Symbol.toStringTag` и `ArrayBuffer[Symbol.species]`. `slice` копирует байты в новый буфер с учётом границ и species.

Проверки Windows: три локальных теста, включая GC stress и `slice`; совместно с тестами глобальных свойств — 16/16. Test262: `ArrayBuffer.prototype.byteLength` 7/10, `ArrayBuffer[Symbol.species]` 4/4, `ArrayBuffer.prototype.slice` 32/33; отдельные тесты конструктора для ToIndex, нулевой и отрицательной длины — 3/3. Единственный отказ `slice` требует SharedArrayBuffer. Три отказа `byteLength` требуют detachment, DataView/typed arrays и SharedArrayBuffer. Linux ELF для ArrayBuffer успешно скомпилирован; исполнение теста пропущено, поскольку WSL недоступен в текущем окружении.

Добавлен `ArrayBuffer.isView`; он распознаёт DataView и текущий Uint8Array, но общий набор typed arrays пока отсутствует. Test262: 12/17; оставшиеся случаи используют весь набор конструкторов typed arrays.

Начата общая основа typed arrays с native `Uint8Array`: конструктор принимает длину или существующий ArrayBuffer со смещением и длиной, объект удерживает backing buffer в GC, а индексные чтение/запись, `in` и `delete` используют специальную ветку runtime. Мутации видны через DataView и наоборот. `ArrayBuffer.isView` распознаёт экземпляры. Локальные проверки ArrayBuffer/DataView/Uint8Array — 20/20, вместе с тестами глобальных свойств — 33/33. Linux ELF собран; выполнение пропущено из-за отсутствия WSL. Полная семантика typed arrays ещё не достигнута: отсутствуют остальные типы, конструирование из iterable/array-like, общий `%TypedArray%` prototype, канонические числовые ключи, методы, итераторы и detachment.

Добавлен native `DataView`: конструктор проверяет ArrayBuffer, смещение и длину, поддерживает наследование; доступны `buffer`, `byteOffset`, `byteLength`, целочисленные методы 8/16/32 бит, `Float32`/`Float64`, `BigInt64`/`BigUint64` и `@@toStringTag`. Ссылка на буфер трассируется GC. Методы BigInt собирают и разбирают значение через две 32-битные половины, без преобразования всего 64-битного значения в Number. Методы проверены на совместном буфере, копии после `slice`, преобразовании аргументов, порядке байтов, `-0`, `NaN` и stress GC. Локальные проверки ArrayBuffer/DataView — 14/14, вместе с тестами глобальных свойств — 27/27. Проверка подкласса DataView в Test262 прошла. Linux ELF собран, выполнение пропущено из-за недоступного WSL.

Методы BigInt DataView и `ArrayBuffer.prototype.slice` используют заранее захваченные встроенные функции. Целевая проверка после подмены `Function.prototype.call`, `Number` и `Math.trunc` прошла. Локальные ArrayBuffer/DataView тесты — 15/15, вместе с глобальными свойствами — 28/28. Test262 для `ArrayBuffer.prototype.slice` остаётся 32/33; единственный отказ требует SharedArrayBuffer.

Осталось реализовать detachment, все typed arrays включая BigInt, их методы, bounds/species/итераторы, а также завершить `ArrayBuffer.isView` и проверки Test262 и Linux. Выделение памяти сейчас ограничено 2³¹−1 байт; при нехватке памяти native allocator завершает процесс с общей ошибкой. Это промежуточное ограничение, не заявка на полную семантику ArrayBuffer.

Для Uint8Array добавлены перечисление индексных свойств, их дескрипторы и Object.defineProperty с записью в общий backing buffer. Несовместимые атрибуты и выход за границы отклоняются. Целевые локальные тесты — 20/20, вместе с глобальными свойствами — 33/33.

Для Uint8Array добавлена классификация канонических числовых ключей: -0, отрицательные, дробные, NaN/Infinity и большие индексы не становятся обычными свойствами и не берутся из прототипа. Обычные строковые ключи, например 01 и 1e0, остаются обычными свойствами. Локальные проверки ArrayBuffer/DataView/Uint8Array — 22/22, вместе с глобальными свойствами — 35/35, включая stress GC.

Uint8Array теперь принимает iterable и array-like источники через внутренний Array.from с заранее захваченной функцией преобразования в Uint8. Значения преобразуются во время итерации; ошибка закрывает итератор. Исправлен переход для числовых свойств обычных Array в defineOwnProperty, выявленный этим путём. Целевой набор Uint8Array и Array.from — 20/20; отдельная проверка с подменой Array.from и stress GC также прошла.

Добавлен общий прототип для typed arrays с Uint8Array.values, keys, entries и Symbol.iterator. Итераторы используют текущие байты backing buffer, проверяют receiver и удерживают источник при stress GC. Остальные методы %TypedArray%.prototype, виды массивов и точная форма конструктора пока отсутствуют.

Добавлен абстрактный конструктор %TypedArray%: он является прототипом Uint8Array, владеет общим prototype и его constructor; прямой вызов и new отклоняются. Геттеры buffer/byteOffset/byteLength/length перенесены на общий прототип. Статический `of` проходит Test262 **7/8**; единственный отказ требует resizable ArrayBuffer.

Статический TypedArray.of (наследуется Uint8Array) вызывает конструктор receiver с числом элементов, проверяет тип и достаточную длину результата, затем последовательно приводит элементы и записывает их в backing buffer. Проверены наследование, ошибочный receiver, короткий результат и GC stress при преобразовании.

Добавлен Int8Array: конструктор по длине, ArrayBuffer и iterable/array-like, общий backing buffer, знаковое чтение индексных байтов, запись с ToInt8, дескрипторы, итераторы, распознавание ArrayBuffer.isView и TypedArray.of. Он использует существующий 1-байтовый layout; 16/32/64-битные виды пока требуют параметризации размера элемента.

Добавлен Uint8ClampedArray с общим backing buffer и точным ToUint8Clamp: NaN/отрицательные значения дают 0, верхняя граница ограничена 255, половины округляются к чётному байту. Одинаковое преобразование используется при присваивании, defineProperty, TypedArray.of и создании из iterable/array-like. Целевые проверки и GC stress прошли; Linux ELF собран, исполнение пропущено из-за недоступного WSL.

Добавлены Uint16Array и Int16Array с двухбайтовыми элементами, проверкой выравнивания byteOffset, раздельными length/byteLength, знаковым чтением, общим ArrayBuffer и little-endian индексной записью. Проверены границы вида на буфер, Object.defineProperty, TypedArray.of, итераторы и GC stress. Linux ELF собран; запуск пропущен, WSL недоступен. Следующие виды требуют 32/64-битные и floating-point операции.

Добавлены Uint32Array и Int32Array с четырёхбайтовыми элементами. Проверены преобразование с переполнением, знаковое и беззнаковое чтение, выравнивание и длина вида, общие байты с DataView, Object.defineProperty, итераторы и GC stress. Целевой регрессионный набор typed arrays и Array.from — 34/34; глобальные свойства — 13/13. Linux ELF собран, запуск пропущен из-за недоступного WSL. Следующие виды требуют 64-битные и floating-point операции; другие методы %TypedArray% также остаются.

Добавлены Float32Array и Float64Array: преобразование через ToNumber, округление Float32 при записи, сохранение NaN, Infinity и -0, доступ через общий ArrayBuffer и DataView. Проверены длина и выравнивание видов, Object.defineProperty, TypedArray.of, итераторы и stress GC. Регрессионный набор typed arrays и Array.from — 36/36; глобальные свойства — 13/13. Linux ELF собран, исполнение пропущено из-за недоступного WSL. Остаются BigInt64Array/BigUint64Array, другие методы %TypedArray%.prototype и detachment.

Добавлены BigInt64Array и BigUint64Array: точная запись/чтение 64-битных значений через BigInt без Number, оборачивание по модулю 2^64, знаковая интерпретация, общий буфер с DataView. Проверены конструкторы, TypedArray.of, Object.defineProperty, запрет Number, итераторы и stress GC. Целевой набор ArrayBuffer/DataView/typed arrays/Array.from — 52/52; глобальные свойства — 13/13. Linux ELF для BigInt видов собран; запуск пропущен из-за недоступного WSL. Остаются detachment и прочие методы %TypedArray%.prototype, а также расширенные проверки Test262.

Добавлен %TypedArray%.prototype.reverse для всех 11 числовых и BigInt видов. Метод меняет байты исходного буфера по элементам и возвращает тот же объект; проверены пустые/нечётные/чётные длины, другие представления того же буфера, 64-битные значения и stress GC. Windows регрессионный набор ArrayBuffer/DataView/typed arrays/Array.from — 54/54. В этой среде теперь удалось выполнить Linux native: полный elf.test.js — 38 успешных, 1 пропуск (отдельная проверка прямого запуска ELF сообщает о недоступном WSL), 0 ошибок; семь целевых Linux-тестов typed arrays — 7/7 без пропусков. Это подтверждает выбранные сценарии, не весь Linux backend.

Добавлен %TypedArray%.prototype.copyWithin для всех видов: ToIntegerOrInfinity и границы аргументов, копирование вперёд/назад при перекрытии, точные байты Float/BigInt и виды с ненулевым byteOffset. Проверены brand, пустые массивы и stress GC во время приведения аргумента. Целевые тесты — 2/2 Windows и 1/1 Linux native. Тайм-аут проверки запуска WSL в тестовом помощнике увеличен с 3 до 10 секунд после нестабильных пропусков при холодном старте; новый Linux-тест выполнился без пропуска. Полный регрессионный прогон после этой правки не запускался; предыдущий Windows набор reverse — 54/54 и Linux elf.test.js — 38 успешных, 1 пропуск, 0 ошибок.

Добавлен %TypedArray%.prototype.fill для всех видов. Значение приводится один раз до вычисления границ; целочисленные, Float32/Float64, Uint8Clamped и BigInt виды записывают соответствующие байты непосредственно в backing buffer. Проверены отрицательные границы, ненулевой byteOffset, NaN/-0, запрет Number для BigInt, пустые массивы и stress GC при приведении значения и start. Целевые тесты — 2/2 Windows и 1/1 Linux native без пропусков. Полный регрессионный набор после fill не запускался.

Добавлены %TypedArray%.prototype.includes, indexOf и lastIndexOf с внутренней длиной вида, независимо от подменённого свойства length. includes использует SameValueZero (включая NaN), indexOf/lastIndexOf — строгое равенство; BigInt сравнивается без Number. Проверены fromIndex, пустые виды, brand и stress GC при приведении fromIndex. Целевые тесты — 2/2 Windows и 1/1 Linux native без пропусков. После добавления copyWithin/fill/поиска выбранный регрессионный набор ArrayBuffer/DataView/typed arrays/Array.from — 60/60 Windows; глобальные свойства — 13/13. Полная группа Test262 typed arrays ещё не запускалась.

Раскрыт каталог TypedArray в закреплённом sparse checkout Test262. Для includes получено 30/45, indexOf 31/43. Группа lastIndexOf выявила граничную ошибку при fromIndex == -length; после исправления — 29/42, оба теста поиска найденного элемента проходят. Для reverse — 16/22, copyWithin до добавления BYTES_PER_ELEMENT — 53/65, fill — 41/52. Отказы в этих группах после исправления lastIndexOf связаны с detachment, resizable/immutable buffers; одна ошибка copyWithin/byteoffset была следствием отсутствующего BYTES_PER_ELEMENT. Свойство добавлено как неизменяемое собственное свойство всех 11 конструкторов и прототипов: его группа Test262 — 22/22, повторный copyWithin/byteoffset — 1/1. Полные группы copyWithin/reverse/fill после BYTES_PER_ELEMENT не повторялись. Detachment остаётся основным пробелом этапа 0.11.

Начата реализация detachment для ArrayBuffer: внутренний host hook используется smoke harness Test262, byteLength отсоединённого буфера равен нулю, DataView и конструкторы видов отвергают отсоединённый буфер, геттеры typed arrays возвращают нулевые размеры, а индексные свойства исчезают. Методы reverse/copyWithin/fill/includes/indexOf/lastIndexOf и итераторы проверяют отсоединение при вызове. Для copyWithin/fill добавлены проверки после приведения аргументов; includes и indexOf/lastIndexOf сохраняют различие в поведении при отсоединении во время fromIndex. Test262: ArrayBuffer.byteLength **9/10** (оставшийся тест требует SharedArrayBuffer); detachment в includes **6/6**, indexOf **6/6**, lastIndexOf **6/6**, fill **5/5**, reverse **2/2**. Три крупных теста copyWithin с массивом из 10 000 элементов превысили 30-секундный лимит smoke runner, поэтому не засчитаны; эквивалентный сценарий на малом массиве прошёл локально. Полный файл Windows тестов буферов — **53/53**; целевой Linux native тест detachment — **1/1**. Полная семантика detachment, SharedArrayBuffer, resizable buffers и оставшиеся методы typed arrays ещё требуют работы.

Добавлен `%TypedArray%.prototype.forEach` с проверкой вида, неизменным снимком длины, актуальным чтением каждого элемента и корректным `thisArg`; локально проверены Number/BigInt, detachment и ошибка callback. Test262: **34/42**; шесть отказов требуют resizable ArrayBuffer (вне ES2020), два — ещё отсутствующий `Reflect.set`. Полная группа includes после detachment — **36/45**; девять отказов требуют resizable ArrayBuffer. Счётчики относятся к закреплённому текущему Test262, который содержит и более новые возможности.

Добавлены `%TypedArray%.prototype.every`, `some`, `find` и `findIndex`: проверка вида и callback, порядок/короткий выход, снимок длины, актуальные значения и `thisArg`. Test262: every **36/44**, some **36/44**, find **32/38**, findIndex **32/38**. Оставшиеся тесты требуют resizable ArrayBuffer; у every/some ещё по два теста требуют `Reflect.set`. Локальный Windows тест и целевой Linux native тест с BigInt прошли. Остальные методы typed arrays ещё не реализованы.

Добавлены `%TypedArray%.prototype.reduce` и `reduceRight` с правильным направлением обхода, явным/неявным accumulator и TypeError для пустого вида без начального значения. Test262: **43/50** для каждого; пять отказов в каждой группе требуют resizable ArrayBuffer, два — `Reflect.set`. Локальный Windows тест и целевой Linux native тест с BigInt прошли.

Добавлены `%TypedArray%.prototype.join` и `toString`: join проверяет typed array, фиксирует длину до преобразования разделителя и читает элементы по порядку; toString использует ту же функцию, что и `Array.prototype.toString`. Test262: join **26/32**, оставшиеся шесть тестов требуют resizable ArrayBuffer; toString **3/3**. Целевые Windows и Linux native тесты с BigInt прошли.

Добавлены `%TypedArray%.prototype.map` и `filter`, `%TypedArray%[Symbol.species]` и внутренний выбор встроенного конструктора по типу вида. Создание результата проверяет тип typed array, достаточную длину и совместимость Number/BigInt; map создаёт результат до callback, filter — после отбора элементов. Test262: map **70/85**, filter **73/87**, Symbol.species **4/4**. Отказы map/filter требуют resizable или immutable buffers либо `Reflect.set`; базовые проверки species и detachment прошли. Локальный Windows и целевой Linux native тесты с BigInt прошли.

Добавлен `%TypedArray%.prototype.set` с отдельными путями для typed array и array-like источника. Для typed array источник определяется по внутреннему kind без чтения подменённого `length`, значения снимком сохраняются до записи при перекрытии; для array-like геттеры читаются последовательно. Проверяются offset, границы и совместимость Number/BigInt; detachment цели во время геттера приводит к пропуску последующих записей. Первый полный Test262 до исправлений — **85/110**; после исправлений целевые восемь ранее неуспешных проверок прошли **8/8**. Остальные отказы полного прогона требуют SharedArrayBuffer, resizable или immutable buffers. Полную группу после исправлений не повторяли. Локальные Windows и Linux native тесты прошли.

Добавлен `%TypedArray%.prototype.subarray`: новый вид разделяет исходный буфер, использует исходные внутренние length/byteOffset, нормализует отрицательные границы и вызывает species с буфером, byteOffset и длиной. Метод преобразует begin/end даже после detachment, а пользовательский species может вернуть другой вид; для этого добавлены внутренние host helpers, скрытые после инициализации runtime. Первый полный Test262 до исправлений — **59/67**; четыре целевых исправленных случая затем прошли **4/4**, остальные четыре отказа требуют resizable ArrayBuffer. Полную группу после исправлений не повторяли. Локальные Windows и Linux native проверки прошли.

Добавлен `%TypedArray%.prototype.slice`: границы и species, точное байтовое копирование для одинакового типа элементов (включая payload NaN), преобразование по элементам для другого совместимого типа и смещение буфера результата. Внутренний copy helper расширен смещением назначения; при species на том же буфере байты копируются последовательно вперёд по алгоритму ES2020. Test262: **80/92**; все 12 отказов требуют resizable или immutable buffers. Локальный Windows и целевой Linux native тесты с BigInt прошли.

Добавлен `%TypedArray%.prototype.sort`: стабильная сортировка снимка элементов, числовой порядок с NaN в конце и -0 перед +0, BigInt без Number, пользовательский comparator и запись обратно в исходный вид. При detachment во время comparator последующие записи пропускаются. Первый полный Test262 до последней правки — **28/36**; исправленный тест `sort-tonumber` затем прошёл **1/1**. Семь оставшихся отказов требуют resizable или immutable buffers. Локальный Windows и целевой Linux native тесты прошли.

Добавлены `%TypedArray%.prototype.toLocaleString` и `BigInt.prototype.toLocaleString`. Метод typed array проверяет внутренний вид, обходит элементы по снимку длины и преобразует результаты методов элементов в строку с подсказкой `string`; BigInt пока использует десятичное представление без локализации. Test262 для typed arrays — **34/39**; пять отказов требуют resizable ArrayBuffer. Целевые Windows и Linux native тесты прошли.

`%TypedArray%.prototype[Symbol.toStringTag]` перенесён с конкретных прототипов на общий accessor. Геттер возвращает имя внутреннего вида даже для отсоединённого буфера и `undefined` для чужого receiver. Test262: **18/18**.

Добавлен `%TypedArray%.from` с отдельными путями для iterable и array-like источников: iterable собирается до создания результата, array-like элементы читаются после создания, mapper вызывается перед записью каждого элемента. При detachment результата последующие записи пропускаются. Test262: **18/21**; три отказа требуют resizable ArrayBuffer. Добавлен внутренний `IsConstructor`, чтобы не читать источник при неконструируемом `this`; целевой Windows тест порядка действий и Linux native тест прошли.

После добавления SharedArrayBuffer повторные группы Test262 `ArrayBuffer.prototype.byteLength` и `ArrayBuffer.prototype.slice` проходят **10/10** и **33/33** соответственно.

Дополнительный аудит Test262 `%TypedArray%.prototype.entries` дал **14/19**.
