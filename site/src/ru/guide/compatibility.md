# Совместимость и ограничения

## Область действия

Nona реализует язык и встроенные объекты нормативного ECMA-262 11-го издания (июнь 2020) для скриптов и ES-модулей. Интернационализация ECMA-402, API браузера и API Node.js — отдельные спецификации; Nona предоставляет только API хоста, перечисленные в [Справочнике](/ru/reference/modules). Контракт завершённости ведётся в [`docs/es2020-contract.md`](https://github.com/40oleg/nona/blob/main/docs/es2020-contract.md). Собственный `Intl` (ECMA-402) в Nona знает только локаль `en`/`en-US`; остальные локали заменяются ею, часовой пояс — UTC.

Релиз описывается как «ES2020 с документированными исключениями» и никогда — как полностью соответствующий ES2020.

## `eval` и `Function` {#eval-and-function}

Nona компилирует заранее, поэтому `eval` и динамическим конструкторам функций нужен исходный текст во время компиляции:

- **Компилируется заранее:** строковый литерал, конкатенация литералов или переменная, которой присваиваются только такие константы (значение сравнивается во время исполнения). Прямой `eval` видит область видимости вызывающего кода, `this`, `arguments`, `new.target` и `super`; косвенные формы (`(0, eval)(…)`, `globalThis.eval(…)`, `eval?.(…)`) выполняются в глобальной области. Вызовы `Function`, `GeneratorFunction`, `AsyncFunction` и `AsyncGeneratorFunction`, все аргументы которых — литералы, компилируются с семантикой CreateDynamicFunction.
- **Не поддерживается:** исходник, вычисленный во время исполнения, spread-аргументы `eval` и `$262.evalScript`. Они бросают:

```text
EvalError: Nona compiles ahead of time: eval and Function need source text known at compile time
```

Это постоянное документированное исключение ([#11](https://github.com/40oleg/nona/issues/11), [контракт ES2020](https://github.com/40oleg/nona/blob/main/docs/es2020-contract.md)): в исполняемых файлах нет интерпретатора или компилятора.

## Производительность

- Массивы, объекты и `Map`/`Set` используют плотное и хеш-хранилище с shapes и инлайн-кэшами, но вызовы, замыкания и выделение памяти всё же работают в несколько раз медленнее, чем в V8; медленные места перечислены на странице [Производительность](/ru/guide/performance).
- Движок RegExp — VM с возвратами, написанная на JavaScript. Шаблон без обратных ссылок и lookaround, который слишком долго перебирает варианты (без флага `u`), доматчивается движком с линейным временем.
- На Windows таймеры просыпаются по системному тику (обычно 15,6 мс).
- JIT нет: код компилируется один раз, заранее, без оптимизации по профилю.

## Подключаемые части runtime

Каждый исполняемый файл содержит runtime, но его крупные необязательные части подключаются, только если программа может до них добраться. Компилятор решает по тексту каждого компилируемого исходника — программы, её модулей и исходников `eval`/`Function` времени компиляции:

| Часть                                       | Размер       | Подключается, если исходник содержит                                                                                                   |
| ------------------------------------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| Движок RegExp                               | около 1 МБ   | литерал RegExp или имя `RegExp`, `match`, `matchAll` или `search` (как свободный идентификатор, имя свойства или строка-ключ свойства) |
| Таблицы свойств Unicode для `\p{…}`/`\P{…}` | около 2 МБ   | `\p{` или `\P{` в литерале RegExp или строке вместе с движком (шаблон может строиться во время исполнения)                             |
| Таблицы нормализации Unicode                | около 0,7 МБ | имя `normalize` или `localeCompare`                                                                                                    |

Имя выбирает часть, если это свободный идентификатор (локальная переменная, параметр или импорт с таким именем ничего не выбирают), имя свойства (`s.normalize()`) или строка в позиции ключа (`s["normalize"]`, `"x" in o`, `Reflect.get(o, "x")`, спецификатор модуля). Обычная строка вроде `console.log("normalize")` или локальная переменная `small` ничего не выбирают. Если программа читает свойства по ключам, которые компилятор не может знать (`o[name]`), учитывается и каждая строка, в точности равная имени. Внутри `with` и в функциях с нестрогим прямым `eval` учитывается каждый идентификатор. Имя свойства выбирает часть независимо от получателя, а код подключённых встроенных модулей учитывается как ваш. Ключи, построенные во время исполнения (`"nor" + "malize"`), не видны: используйте `--link` или `--full-runtime` ([#438](https://github.com/40oleg/nona/issues/438)).

`split`, `replace` и `replaceAll` со строковыми аргументами движок RegExp не требуют.

Встроенные библиотеки на JavaScript, которые лишь устанавливают глобальные объекты или методы (около 0,7 МБ вместе), подключаются так же, если исходник содержит одно из их имён:

| Часть                                                                                                                                                                  | Имена                                                                                                                                         |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `Proxy`                                                                                                                                                                | `Proxy`                                                                                                                                       |
| `TextEncoder`, `TextDecoder`                                                                                                                                           | `TextEncoder`, `TextDecoder` (подключаются также вместе с `process`)                                                                          |
| `process`                                                                                                                                                              | `process`                                                                                                                                     |
| Таймеры, цикл событий, `queueMicrotask` и `performance`                                                                                                                | `setTimeout`, `setInterval`, `setImmediate`, `clearTimeout`, `clearInterval`, `clearImmediate`, `queueMicrotask`, `performance`, `globalThis` |
| `.at()`, `findLast`, `findLastIndex`, `Object.hasOwn`, `Object.groupBy`, `Map.groupBy`, `AggregateError`, `Promise.any`, `toSorted`, `toReversed`, `toSpliced`, `with` | `at`, `findLast`, `findLastIndex`, `hasOwn`, `groupBy`, `AggregateError`, `any`, `unscopables`                                                |
| `String.prototype.isWellFormed` и `toWellFormed`                                                                                                                       | `isWellFormed`, `toWellFormed`                                                                                                                |
| `RegExp.escape`                                                                                                                                                        | `escape`                                                                                                                                      |
| Iterator helpers (`Iterator`, `Iterator.from`, `map`, `take`, `drop`, `flatMap`, `toArray`, …)                                                                         | `Iterator`, `toArray`, `take`, `drop`, `flatMap`                                                                                              |
| `escape`, `unescape`, `substr`, `setYear`, `toGMTString`, `RegExp.prototype.compile` из Annex B и HTML-методы строк (`anchor`, `big`, `link`, …)                       | те же имена                                                                                                                                   |
| Устойчивая сортировка слиянием `Array.prototype.sort`                                                                                                                  | `sort`                                                                                                                                        |
| Intl (только en/en-US, [docs/intl.md](https://github.com/40oleg/nona/blob/main/docs/intl.md))                                                                          | `Intl`, `toLocaleString`, `toLocaleDateString`, `toLocaleTimeString`, `localeCompare`                                                         |
| `Object.freeze`, `seal`, `isFrozen`, `isSealed` через ловушки Proxy (для обычных объектов используются нативные версии)                                                | те же имена                                                                                                                                   |
| `__defineGetter__`, `__defineSetter__`, `__lookupGetter__`, `__lookupSetter__`                                                                                         | те же имена                                                                                                                                   |
| Методы двоичных данных `ArrayBuffer`, `SharedArrayBuffer`, `DataView` и типизированных массивов (`slice`, `subarray`, `sort`, …)                                       | имена их конструкторов, `Atomics`, `TypedArray` (подключаются и с `process`, `Buffer` и `TextEncoder`)                                        |
| Методы протокола RegExp и String (`Symbol.replace`, `String.prototype.match`, `matchAll`, `search`, `replaceAll`, …)                                                   | вместе с движком RegExp или `replaceAll`                                                                                                      |

Программа, которая вызывает `Object.getOwnPropertyNames`, `Object.getOwnPropertyDescriptors` или `Reflect.ownKeys`, подключает все части, так как может перечислить встроенные объекты ([#84](https://github.com/40oleg/nona/issues/84)). Hello world весит около 1,1 МБ; со всеми частями — 7 МБ.

Хелперы, нужные только некоторому синтаксису, подключаются, когда их вызывает скомпилированная программа, а не по именам: оператор `with`, литеральный `eval`, поля классов и приватные имена, ES-модули с `import()` и `import.meta` ([#278](https://github.com/40oleg/nona/issues/278)).

Программа всё же может добраться до пропущенной части через имя, вычисленное во время исполнения, например `globalThis['Reg' + 'Exp']`. Для движка RegExp и таблиц Unicode такой вызов бросает `Error`, в сообщении которого названа отсутствующая часть; пропущенный глобальный объект или метод просто отсутствует. Чтобы подключить всё, компилируйте с `--full-runtime` (или параметром `fullRuntime` функции [`compile()`](/ru/reference/api)) ([#62](https://github.com/40oleg/nona/issues/62)). Отдельные части можно добавить через `--link часть,...`, а `--print-link` показывает, что подключено и какое имя выбрало каждую часть ([#182](https://github.com/40oleg/nona/issues/182)).

## Realms

`$262.createRealm` поддерживается для Test262. Функции, классы и eval-код, созданные из литерального исходника через `Function`, `eval` или динамические конструкторы функций другого realm, выполняются в этом realm, а прототипы по умолчанию и ошибки конструкторов берутся из realm, который указывает ECMA-262 ([#7](https://github.com/40oleg/nona/issues/7), [#176](https://github.com/40oleg/nona/issues/176)).

## Платформы

- `process` и `node:fs` доступны на всех восьми целях; HTTP и TCP (`node:http`, `node:net`) — на Windows и Linux.
- Исполняемые файлы Windows используют DLL ОС (включая NTDLL для метаданных родительского процесса) и объявленные импорты FFI; исполняемые файлы POSIX используют нативные службы ОС.
- FFI вызывает DLL в Windows и разделяемые библиотеки (`.so`, `.dylib`) в Linux и macOS, с переносимыми объявлениями по ОС; цели BSD имеют только прямые системные вызовы. Прямые системные вызовы используют номера ядра выбранной цели Linux, Darwin или BSD. Подробности: [Нативные платформы](/reference/native-platforms).

## Buffer

Глобальные `Buffer`, `Blob` и `File`, а также импорты `node:buffer` / `buffer` / `nona:buffer` доступны на каждой нативной цели. Buffer поддерживает стандартные байтовые кодировки, общие срезы, копирование, поиск и числовой доступ. Blob/File поддерживают неизменяемые данные и метаданные. Доступны байтовые и текстовые потоки Blob, а также регистрация и разрешение объектных URL; см. [контракт API и ограничения](/reference/host-apis#buffer-and-binary-data).
