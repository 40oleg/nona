# Что такое Nona

Nona — компилятор JavaScript ahead-of-time. Он читает скрипт или граф ES-модулей, проверяет его, переводит в собственное промежуточное представление, генерирует машинный код x86-64 и собирает самостоятельный исполняемый файл: образ PE32+ для Windows или ELF64 для Linux.

Компилятор написан на TypeScript и работает в Node.js. Программы, которые он создаёт, — нет: в них нет интерпретатора, V8 и байт-кода. Исполняемый файл для Windows импортирует только `KERNEL32.dll` (и DLL, которые программа вызывает через [FFI](/ru/reference/ffi)); исполняемый файл для Linux делает системные вызовы напрямую и не использует libc.

## Что вы получаете

- **Язык ES2020.** Классы и `super`, генераторы, async-функции и async-генераторы, `for await`, деструктуризация, spread, optional chaining, `??`, BigInt, Symbol, итераторы, proper tail calls, `with` в нестрогом режиме и семантика веб-совместимости Annex B.
- **ES-модули.** Статические `import`/`export`, циклы и live bindings, `import.meta` и динамический `import()` модулей, известных при компиляции. Файлы `.mjs` компилируются как модули.
- **Стандартная библиотека ES2020.** Object, Function, Array, String, Number, Math, Date, JSON, RegExp (именованные группы, lookbehind, флаги `s` и `u`, Unicode property escapes), Map, Set, WeakMap, WeakSet, ArrayBuffer, DataView и все typed arrays, SharedArrayBuffer и Atomics, Proxy и Reflect, Promise с очередью jobs.
- **`eval` и `Function` с исходником, известным при компиляции.** Строковый литерал, конкатенация литералов или переменная, которой присваиваются только такие константы, компилируются заранее с полной семантикой прямого и косвенного `eval`.
- **Нативный runtime.** Точный немещающий mark-and-sweep сборщик мусора, строки UTF-16, настоящие исключения и перехватываемый `RangeError` при переполнении стека.
- **API хоста** для настоящих программ: [цикл событий с таймерами](/ru/reference/host-apis), глобальный [`process`](/ru/reference/process), синхронный [`node:fs`](/ru/reference/fs) с `TextEncoder`/`TextDecoder` и [вызовы нативных функций](/ru/reference/ffi) с готовыми объявлениями `nona:win32`.
- **Быстрый запуск и малый размер.** Скомпилированный hello world стартует примерно за 2 мс, занимает не больше 11 МБ памяти, а сам файл весит 3 МБ: нет runtime, который надо загружать, и нет JIT, который надо прогревать ([Производительность](/ru/guide/performance)).
- **Исполняемые файлы Windows** без консольного окна, с иконкой, манифестом и сведениями о версии ([Исполняемые файлы Windows](/ru/reference/windows-executables)).

## Чем Nona не является

- **Не замена Node.js.** Нет `require`, пакетов npm и API Node.js, кроме [подмножеств `fs` и `process`](/ru/reference/modules). API браузера тоже недоступны.
- **Не полная реализация ES2020.** Nona реализует ES2020 с документированными исключениями; см. [Поддержку языка](/ru/guide/language-support) и [Совместимость и ограничения](/ru/guide/compatibility).
- **Нет генерации кода во время исполнения.** `eval` и `Function` требуют исходник, известный при компиляции; строки, вычисленные во время исполнения, бросают `EvalError`.
- **Пока не быстр в вычислениях.** Без JIT вызовы, доступ к свойствам и выделение памяти в 20–100 раз медленнее, чем в V8, а `Map`/`Set`, `sort`, сборка строк и длинные цепочки Promise пока растут сверхлинейно от объёма данных ([Производительность](/ru/guide/performance)).
- **Не переносим за пределы x86-64.** Цели — Windows 10/11 x64 и Linux x86-64.

## Безопасность

Nona не проходил аудит безопасности. Не компилируйте недоверенный исходный код и не считайте сгенерированные исполняемые файлы песочницей: они работают с теми же правами, что и любая другая нативная программа, а через FFI можно вызвать любую DLL.
