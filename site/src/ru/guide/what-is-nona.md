# Что такое Nona

Nona — компилятор JavaScript ahead-of-time. Он читает скрипт или граф ES-модулей, проверяет его, переводит в собственное промежуточное представление, генерирует машинный код x86-64 или AArch64 и собирает выходной файл PE32+, ELF64 или Mach-O64.

Компилятор написан на TypeScript. Он работает в Node.js или как выпущенный нативный исполняемый файл `nona`, который Nona собрал из исходников самого компилятора. Создаваемым программам не нужно ни то, ни другое: в них нет интерпретатора, V8 и байт-кода. Исполняемый файл для Windows импортирует только `KERNEL32.dll` (и DLL, которые программа вызывает через [FFI](/ru/reference/ffi)); исполняемый файл для Linux делает системные вызовы напрямую и не использует libc.

## Что вы получаете

- **Язык ES2020.** Классы и `super`, генераторы, async-функции и async-генераторы, `for await`, деструктуризация, spread, optional chaining, `??`, BigInt, Symbol, итераторы, proper tail calls, `with` в нестрогом режиме и семантика веб-совместимости Annex B.
- **ES-модули.** Статические `import`/`export`, циклы и live bindings, `import.meta` и динамический `import()` модулей, известных при компиляции. Файлы `.mjs` компилируются как модули.
- **Стандартная библиотека ES2020.** Object, Function, Array, String, Number, Math, Date, JSON, RegExp (именованные группы, lookbehind, флаги `s` и `u`, Unicode property escapes), Map, Set, WeakMap, WeakSet, ArrayBuffer, DataView и все typed arrays, SharedArrayBuffer и Atomics, Proxy и Reflect, Promise с очередью jobs.
- **`eval` и `Function` с исходником, известным при компиляции.** Строковый литерал, конкатенация литералов или переменная, которой присваиваются только такие константы, компилируются заранее с полной семантикой прямого и косвенного `eval`.
- **Нативный runtime.** Точный немещающий mark-and-sweep сборщик мусора, строки UTF-16, настоящие исключения и перехватываемый `RangeError` при переполнении стека.
- **API хоста в стиле Node.js** для настоящих программ: [цикл событий с таймерами](/ru/reference/host-apis), [`process`](/ru/reference/process), [`node:fs`](/ru/reference/fs), `path`, `Buffer`, потоки, события, `URL`, [HTTP и TCP](/reference/network) и [вызовы нативных функций](/ru/reference/ffi) с готовыми объявлениями `nona:win32`. Все они перечислены в разделе [Встроенные модули](/ru/reference/modules).
- **Восемь целевых платформ.** Windows, Linux и macOS на x64 и ARM64, FreeBSD и OpenBSD на x64; кросс-компиляция с любого хоста ([Нативные платформы](/reference/native-platforms)).
- **Пакеты npm.** Пакеты из `node_modules` разрешаются при сборке и компилируются в исполняемый файл ([пакеты npm](/reference/npm)).
- **Быстрый запуск и малый размер.** Скомпилированный hello world стартует примерно за 2 мс, занимает не больше 11 МБ памяти, а сам файл весит около 2 МБ (до 7 МБ, если программа задействует все необязательные части runtime): нет runtime, который надо загружать, и нет JIT, который надо прогревать ([Производительность](/ru/guide/performance)).
- **Исполняемые файлы Windows** без консольного окна, с иконкой, манифестом и сведениями о версии ([Исполняемые файлы Windows](/ru/reference/windows-executables)).

## Чем Nona не является

- **Не замена Node.js.** Пакеты npm компилируются в программу при сборке ([пакеты npm](/reference/npm)), но доступны только [API Node.js, реализованные в Nona](/ru/reference/modules), а пакеты, которым нужны другие API (`https`, `child_process`), `Intl` (кроме `Intl.Segmenter`) или нативные дополнения, не работают. API браузера тоже недоступны.
- **Не полная реализация ES2020.** Nona реализует ES2020 с документированными исключениями; см. [Поддержку языка](/ru/guide/language-support) и [Совместимость и ограничения](/ru/guide/compatibility).
- **Нет генерации кода во время исполнения.** `eval` и `Function` требуют исходник, известный при компиляции; строки, вычисленные во время исполнения, бросают `EvalError`.
- **Не так быстр, как V8, в вычислениях.** Без JIT вызовы, замыкания и выделение памяти работают в несколько раз или в десятки раз медленнее, чем в V8, а самые медленные места — длинные цепочки Promise и сопоставление RegExp ([Производительность](/ru/guide/performance)).
- **Не одинаков на всех платформах.** API файловой системы и сети, FFI и некоторые возможности `process` зависят от цели; см. [Нативные платформы](/reference/native-platforms).

## Безопасность

Nona не проходил аудит безопасности. Не компилируйте недоверенный исходный код и не считайте сгенерированные исполняемые файлы песочницей: они работают с теми же правами, что и любая другая нативная программа, а через FFI можно вызвать любую DLL.
