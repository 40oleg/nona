# Нативные функции (FFI)

::: info Перевод
Это перевод английской страницы [Native functions (FFI)](/reference/ffi), созданной из [`docs/ffi.md`](https://github.com/40oleg/nona/blob/main/docs/ffi.md). Английская версия — основная и может быть новее.
:::

Программы могут вызывать экспортируемые функции разделяемых библиотек через встроенный модуль `nona:ffi`: DLL в Windows, разделяемые объекты (`.so`) в Linux и dylib или фреймворки в macOS. Объявления разрешаются при компиляции: каждый вызов `define` добавляет запись в таблицу импорта исполняемого файла (таблица импорта PE, динамическая секция ELF или таблица привязок Mach-O), поэтому программа не использует `LoadLibrary`/`GetProcAddress` или `dlopen`/`dlsym`, а загрузчик операционной системы разрешает все символы до запуска программы.

```js
import { define, lastError } from "nona:ffi";

const MessageBoxW = define(
    "user32.dll",
    "MessageBoxW",
    "i32(ptr,wstr,wstr,u32)",
);
MessageBoxW(null, "Hello from Nona", "Nona", 0);
```

```js
import { define, lastError } from "nona:ffi";

const strlen = define(
    {
        win32: "ucrtbase.dll",
        linux: "libc.so.6",
        darwin: "/usr/lib/libSystem.B.dylib",
    },
    "strlen",
    "u64(str)",
);
const cos = define(
    {
        win32: "ucrtbase.dll",
        linux: "libm.so.6",
        darwin: "/usr/lib/libSystem.B.dylib",
    },
    "cos",
    "f64(f64)",
);
console.log(strlen("hello"), cos(0)); // 5 1
```

- FFI доступен в коде модулей (`.mjs` или `--module`). `define` нужно вызывать напрямую с тремя литералами: библиотека, имя символа и сигнатура. Всё остальное — ошибка компиляции (`E_FFI_STATIC`).
- Библиотека — строковый литерал или **переносимое объявление**: объектный литерал из строковых литералов с ключами по операционной системе (`win32`, `linux`, `darwin`). Компилятор выбирает ключ цели; цель без ключа — ошибка компиляции (`E_FFI_TARGET`). Объявления в любом случае остаются статическими: во время выполнения ключи не читаются.
- `lastError()` возвращает код ошибки, сохранённый сразу после последнего вызова FFI: `GetLastError()` в Windows, `errno` в Linux и macOS. Как и сам `errno`, он осмыслен после вызова, сообщившего об ошибке; успешный вызов может оставить старое значение.
- В Linux, Darwin и BSD `define('syscall', '<number>', signature)` объявляет прямой системный вызов (не больше шести целочисленных аргументов или аргументов `buf`; результат — сырое значение, возвращённое ядром, при ошибке — отрицательный `errno`). Объявления системных вызовов отклоняются для целей Windows. Номера принадлежат выбранному ядру и процессору; Darwin использует номер BSD без префикса класса `0x2000000`. Ошибки BSD/Darwin через флаг переноса нормализуются в отрицательный `errno`. Системный вызов не обновляет `lastError()`; смотрите его результат.
- Если библиотеки или символа нет, загрузчик операционной системы отказывается запускать программу (Windows сообщает об отсутствующей DLL; `ld.so` печатает `symbol lookup error` и завершается с кодом 127; dyld сообщает об отсутствующем символе).

| Цель                     | Аргумент библиотеки                                                                                                                               | Механизм                                                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| win32-x64, win32-arm64   | имя DLL без пути (`kernel32.dll`, `ucrtbase.dll`)                                                                                                 | таблица импорта PE                                                                                                |
| linux-x64, linux-arm64   | soname или путь (`libc.so.6`, `libm.so.6`, `libsqlite3.so.0`, `/opt/lib/libfoo.so`)                                                               | динамически линкуемый ELF: `PT_INTERP`, `DT_NEEDED`, релокации `GLOB_DAT`, разрешаемые при старте (`DT_BIND_NOW`) |
| darwin-x64, darwin-arm64 | путь к dylib или бинарнику фреймворка (`/usr/lib/libSystem.B.dylib`, `/usr/lib/libsqlite3.dylib`, `/System/Library/Frameworks/Foo.framework/Foo`) | dyld: по одному `LC_LOAD_DYLIB` на библиотеку, привязка на каждый символ                                          |
| freebsd-x64, openbsd-x64 | —                                                                                                                                                 | только системные вызовы; объявление библиотеки — `E_FFI_TARGET`                                                   |

Имя DLL Windows для цели Linux или macOS, как и имя `.so`/`.dylib` для Windows, — тоже `E_FFI_TARGET`: используйте переносимое объявление.

## Сигнатуры {#signatures}

`result(param, param, ...)`, например `bool(u32,u32,wstr,u32)`.

| Тип                             | Параметр                                                                                                                                  | Результат                                           |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| `i8 i16 i32 i64 u8 u16 u32 u64` | Number (с отбрасыванием дробной части в сторону нуля) или Boolean                                                                         | Number                                              |
| `ptr`                           | Number, Boolean, `null`/`undefined` (NULL)                                                                                                | Number                                              |
| `bool`                          | как `i32`                                                                                                                                 | Boolean (Win32 `BOOL`, ненулевое значение — `true`) |
| `f32 f64`                       | Number                                                                                                                                    | Number                                              |
| `wstr`                          | String → временная копия UTF-16 с завершающим NUL; `null`/`undefined` → NULL                                                              | —                                                   |
| `str`                           | String → временная копия UTF-8 с завершающим NUL; `null`/`undefined` → NULL                                                               | —                                                   |
| `buf`                           | ArrayBuffer, SharedArrayBuffer, typed array или DataView → указатель на его байты (со смещением представления); `null`/`undefined` → NULL | —                                                   |
| `void`                          | —                                                                                                                                         | `undefined`                                         |

Аргументы других типов бросают `TypeError`, как и отсутствующие аргументы (кроме указательных типов, где `undefined` означает NULL) и отсоединённые буферы. Вызываемая функция может писать в память `buf` — так возвращаются выходные параметры: передайте `Uint16Array` для буфера строки UTF-16 или `Uint8Array(8)` для дескриптора. Временные копии строк освобождаются после вызова; вызываемая функция не должна сохранять указатель. Callbacks (`cb(...)`) и типы выходных параметров зарезервированы для следующих версий. Функция принимает не больше 32 параметров.

`bool` — 32-битное целое (`BOOL`, `int`). Для результата C `_Bool`/`bool`, старшие биты которого не определены, объявите `u8` и сравните с `0`.

## Linux и macOS

- **Соглашения о вызовах.** linux-x64 и darwin-x64 используют SysV AMD64 ABI (целочисленные аргументы в RDI, RSI, RDX, RCX, R8, R9, аргументы с плавающей точкой в XMM0–XMM7, остальные в стеке; `AL` содержит число векторных регистров, поэтому вариативные функции вроде `snprintf` получают аргументы `int` и `double` корректно на x86-64). linux-arm64 использует AAPCS64 (X0–X7, D0–D7, затем стек по 8 байт на аргумент); darwin-arm64 — вариант Apple, где стековые аргументы упаковываются по естественному размеру и выравниванию, а аргументы `i8`/`i16`/`u8`/`u16` расширяет вызывающая сторона. Nona расширяет узкие целочисленные аргументы на всех целях POSIX. Вариативные функции на ARM64 не поддерживаются (Apple передаёт вариативные аргументы через стек): объявляйте только фиксированные параметры и избегайте там вариативных вызовов.
- **Библиотеки.** Исполняемые файлы Linux называют загрузчик GNU C library (`/lib64/ld-linux-x86-64.so.2`, `/lib/ld-linux-aarch64.so.1`) и всегда требуют `libc.so.6` (для `errno`); они не запускаются на системах с musl, например Alpine. soname (`libm.so.6`) ищется как зависимость любой программы (`LD_LIBRARY_PATH`, системный кэш, `/lib`, `/usr/lib`); имя с косой чертой — путь. В macOS системные библиотеки находятся в общем кэше dyld и называются по пути установки; простое имя файла ищется в `DYLD_LIBRARY_PATH` и резервных путях.
- **Статический файл без объявлений.** Программа без объявлений библиотек — тот же статический исполняемый файл без libc, что и раньше (Linux), или сохраняет запуск ядром (macOS на Intel); динамически линкуется только программа, объявившая библиотечную функцию. Вывод для Apple Silicon всегда использует dyld и libSystem.
- **Состояние библиотеки C.** Загрузчик инициализирует libc (локальное хранилище потока, `environ`, данные локали) до запуска программы, а рантайм Nona не меняет указатель потока, поэтому функции libc видят своё состояние. Рантайм создаёт собственные потоки (агенты, `Worker`) через `clone` без собственного локального хранилища потока: вызывайте библиотечные функции из главного потока. Nona завершается через ядро, а не `exit()`, поэтому буферы C `stdio` сбрасывайте сами (`fflush(NULL)`), если библиотека писала через них. Библиотечные функции, устанавливающие обработчики сигналов, могут мешать `process.on('SIGINT')`.
- **`lastError()`** читает `errno` через `__errno_location` (glibc) или `__error` (Darwin) сразу после вызова, прежде чем другой вызов библиотеки его изменит.
- Результат можно проверить через `readelf -d -l` (`NEEDED`, `BIND_NOW`, `INTERP`) или `otool -L` / `dyld_info -bind` в macOS.

## `nona:win32` {#nona-win32}

Подобранный набор объявлений и вспомогательных функций на основе `nona:ffi`:

- user32: `MessageBoxW`, `GetSystemMetrics`, `SystemParametersInfoW` (строковый параметр), `SystemParametersInfoBufferW` (параметр-буфер);
- kernel32: `CreateMutexW`, `ReleaseMutex`, `CloseHandle`, `GetModuleFileNameW`, `GetCurrentProcessId`;
- advapi32: `RegCreateKeyExW`, `RegOpenKeyExW`, `RegSetValueExW`, `RegQueryValueExW`, `RegDeleteValueW`, `RegDeleteKeyW`, `RegCloseKey`;
- константы, например `HKEY_CURRENT_USER`, `KEY_ALL_ACCESS`, `REG_SZ`, `SPI_SETDESKWALLPAPER`, `SPIF_UPDATEINIFILE`, `ERROR_ALREADY_EXISTS`;
- вспомогательные функции `wideString(text)` (`Uint16Array` с завершающим NUL), `fromWideString(buffer)` и `readHandle(buffer)`; `lastError` реэкспортируется.

```js
import {
    SystemParametersInfoW,
    SPI_SETDESKWALLPAPER,
    SPIF_UPDATEINIFILE,
    SPIF_SENDCHANGE,
} from "nona:win32";
SystemParametersInfoW(
    SPI_SETDESKWALLPAPER,
    0,
    "C:\\Pictures\\painting.jpg",
    SPIF_UPDATEINIFILE | SPIF_SENDCHANGE,
);
```

`nona:win32` объявляет DLL, поэтому его импорт требует цели Windows.
